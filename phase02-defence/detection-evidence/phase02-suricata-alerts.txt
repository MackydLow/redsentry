Rule 9000006 (SSH Brute Force) — untested, documented limitation:

Attempted to trigger this rule via repeated failed SSH login attempts
against Metasploitable's OpenSSH server. The connection failed at the
SSH key-exchange/negotiation stage before authentication was ever
attempted:

  "Unable to negotiate with 192.168.128.8 port 22: no matching host key
  type found. Their offer: ssh-rsa,ssh-dss"

Modern OpenSSH clients (as shipped in current Kali) have deprecated and,
in some cases, entirely removed support for legacy host key types
(ssh-dss) and key-exchange algorithms that Metasploitable's ~2012-era
SSH server requires — attempts to explicitly re-enable these via
HostKeyAlgorithms/KexAlgorithms client options were rejected outright
by the SSH client itself ("Bad key types"), rather than negotiating
successfully.

This means the connection never reaches the authentication stage,
so no auth-failure events are generated for Suricata to detect,
regardless of how many connection attempts are made.

Rule syntax was validated and loaded successfully by Suricata (see
Phase 02 config validation); only live-fire testing against this
specific target was not achievable.
